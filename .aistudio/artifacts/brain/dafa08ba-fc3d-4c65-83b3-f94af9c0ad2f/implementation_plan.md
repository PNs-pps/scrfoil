# แผนการปรับปรุง (ฉบับอัปเดต): ปรับ Logic การกด Enter ให้ทำงานต่อเนื่อง (SO → เมตร → NG → สร้างแถว SO ใหม่) ทั้งในระบบตัด PU Sandwich และระบบตัดฟอยล์

## 1. ที่มาและพฤติกรรมที่ต้องการ (User Requirements)
ผู้ใช้งานต้องการให้ขั้นตอนการคีย์ข้อมูลในระบบตัดสต๊อก **ทั้ง 2 โมดูลหลัก (ตัด PU Sandwich และตัดฟอยล์)** สามารถใช้แป้นพิมพ์กดปุ่ม `Enter` ทำงานต่อเนื่องได้อย่างสมบูรณ์แบบ:
1. **ช่องรหัส SO:** กรอกรหัสเสร็จ กด `Enter` → เลื่อนโฟกัสไปที่ช่อง **ความยาวเมตร (เมตรที่ตัดใช้)**
2. **ช่องความยาวเมตร:** กรอกเมตรเสร็จ กด `Enter` → เลื่อนโฟกัสไปที่ช่อง **ของเสีย NG**
3. **ช่องของเสีย NG:** กด `Enter`:
   - หากไม่ได้กรอกค่า ให้บันทึกเป็น `0` อัตโนมัติ
   - หากมีแถวถัดไปอยู่แล้ว ให้เลื่อนไปที่รหัส SO ของแถวถัดไป
   - หากเป็นแถวสุดท้าย ให้สร้างแถว SO ใหม่ทันที
   - เคอร์เซอร์ไปโฟกัสที่ **ท้ายรหัส SO ของแถวใหม่** ทันที (เช่น `so6904|`) เพื่อให้ผู้ใช้สามารถพิมพ์เลขต่อได้โดยไม่ต้องใช้เมาส์คลิก

## 2. การปรับปรุงในระบบตัด PU Sandwich (`src/components/PuSandwichModal.tsx`)

### 2.1 เพิ่ม `onKeyDown` ให้กับช่องความยาวตามใบงาน SO (`soLengthMeters`)
* ปัจจุบัน input ความยาว SO ไม่มี `onKeyDown` ทำให้เมื่อกด Enter โค้ดจะถูกดักจับและยกเลิกโดย `handleModalKeyDown`
* เพิ่ม `onKeyDown={(e) => handleRowKeyDown(e, row, 'soLengthMeters')}` เพื่อส่งต่อโฟกัสไปยัง `soNgInputRefs.current[row.id]`

### 2.2 ปรับปรุง `handleRowKeyDown` ในส่วนของช่อง `ngKg`
* เมื่อผู้ใช้กด Enter ในช่อง `ngKg`:
  1. หากผู้ใช้ไม่ได้พิมพ์ตัวเลข (`!row.ngKg.trim()`) ให้เซตค่าเป็น `'0'` อัตโนมัติ (`handleRowNgKgChange(row.id, '0')`)
  2. ตรวจสอบว่ามีแถวถัดไปหรือไม่:
     - หากมีแถวถัดไป → โฟกัสไปที่ `soNumberInputRefs.current[nextRow.id]`
     - หากไม่มีแถวถัดไป → เรียก `handleAddRow()` เพื่อสร้างแถวใหม่
  3. ใน `handleAddRow()` จะโฟกัสและวางเคอร์เซอร์ไว้ท้ายสตริงรหัส SO เริ่มต้น (`setSelectionRange(len, len)`)

## 3. การปรับปรุงในระบบตัดฟอยล์ (`src/components/CutStockModal.tsx`)

### 3.1 ปรับปรุง Flow การกด Enter จากช่อง `ngMeters`
* ใน input `ngMeters`:
  1. เมื่อกด Enter หากไม่ได้พิมพ์ค่า (`!order.ngMeters.trim()`) ให้เซตเป็น `'0'` อัตโนมัติ (`handleUpdateOrder(order.id, { ngMeters: '0' })`)
  2. ตรวจสอบแถวถัดไป:
     - หากมีแถวถัดไป (`orders[index + 1]`) → โฟกัสไปที่ `soInputRefs.current[orders[index + 1].id]`
     - หากเป็นแถวสุดท้าย → เรียก `handleAddOrder()` เพื่อสร้างแถว SO ใหม่
  3. ใน `handleAddOrder()` โฟกัสไปที่ `soInputRefs.current[newOrder.id]` และวางเคอร์เซอร์ไว้ท้ายสตริงรหัส SO เริ่มต้น (`setSelectionRange(len, len)`) ทันที

### 3.2 ตรวจสอบความต่อเนื่องของ `soNumber` และ `usedMeters`
* ตรวจสอบว่า `soNumber` กด Enter ไป `usedMeters` พร้อม select ข้อความ และ `usedMeters` กด Enter ไป `ngMeters` พร้อม select ข้อความ ทำงานได้อย่างแม่นยำ

## 4. แผนการตรวจสอบและทดสอบ (Verification Plan)

### 4.1 ทดสอบระบบตัด PU Sandwich (`PuSandwichModal`):
1. เปิดหน้าต่างตัด PU Sandwich กรอกรหัส SO แล้วกด `Enter` → ตรวจสอบว่าโฟกัสกระโดดไปช่องความยาว (ม.)
2. กรอกความยาว (ม.) แล้วกด `Enter` → ตรวจสอบว่าโฟกัสกระโดดไปช่อง NG (กก.)
3. ในช่อง NG กด `Enter` โดยไม่พิมพ์อะไร → ตรวจสอบว่าขึ้นค่า 0 กก. และมีแถว SO ที่ 2 ถูกสร้างขึ้น พร้อมเคอร์เซอร์กระพริบต่อท้ายรหัส SO ใหม่
4. พิมพ์เลขต่อแล้วกด `Enter` ซ้ำ → ตรวจสอบว่าวนลูปได้ต่อเนื่องอย่างราบรื่น

### 4.2 ทดสอบระบบตัดฟอยล์ (`CutStockModal`):
1. เปิดหน้าต่างตัดฟอยล์ กรอกรหัส SO แล้วกด `Enter` → กระโดดไปช่องเมตรที่ตัดใช้
2. กรอกเมตรที่ตัดใช้แล้วกด `Enter` → กระโดดไปช่อง NG หัวท้าย
3. ในช่อง NG กด `Enter` โดยไม่พิมพ์อะไร → ตรวจสอบว่าขึ้นค่า 0.00 ม. และมีใบสั่งตัด SO ที่ 2 เพิ่มขึ้นมาทันที พร้อมเคอร์เซอร์กระพริบท้ายรหัส SO ใหม่
