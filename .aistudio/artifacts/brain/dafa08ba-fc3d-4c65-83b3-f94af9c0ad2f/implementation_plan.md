# แผนการพัฒนาระบบตรวจสอบประวัติ SO (SO History Audit Trail & Change Diff)

ตามคำขอและคำสั่งอัปเดตล่าสุดของผู้ใช้:
1. **วัตถุประสงค์หลัก**: บันทึกและติดตามประวัติการแก้ไข (Edit / Update) รายการตัด SO ทุกครั้ง (ยกเลิกการบันทึกประวัติการ "ลบ" ตามคำสั่งล่าสุด)
2. **ตำแหน่งการแสดงผล**: เชื่อมต่อเป็นแท็บ/มุมมองในหน้าประวัติการตัด (`CuttingHistoryTable`) พร้อมปุ่มลัดดูประวัติราย SO ใน `SODetailModal`
3. **ระดับความละเอียดของข้อมูล**: แสดงผลเปรียบเทียบค่าแบบ Full Diff (ค่าเดิม vs ค่าใหม่) พร้อมแสดงชื่อผู้ดำเนินการ (Operator/Staff) และวันเวลาอย่างครบถ้วน
4. **ขอบเขตการทำงาน**: **ไม่บันทึกประวัติการลบ (DELETE)** — หากมีการลบรายการจะทำการคืนสต๊อกปกติโดยไม่เก็บ Audit Log การลบ

---

## 1. การออกแบบโครงสร้างข้อมูล (Data Model & Schema)

### 1.1 อินเตอร์เฟส `SOAuditLogItem` (`src/types.ts`)
* `id`: รหัสบันทึก Audit (UUID/Timestamp-based)
* `timestamp`: วันที่และเวลาที่เกิดเหตุการณ์ (ISO 8601)
* `action`: ประเภทเหตุการณ์ (`UPDATE` / การแก้ไขข้อมูล)
* `recordType`: ประเภทวัตถุดิบ (`foil` | `sandwich`)
* `recordId`: รหัสของใบตัดต้นทาง (`StockCutRecord.id` หรือ `PuSandwichCutRecord.id`)
* `soNumber`: รหัส SO หรือเหตุผล Non-SO ที่เกี่ยวข้อง
* `operator`: ชื่อช่าง/เจ้าหน้าที่ผู้ดำเนินการ (พร้อมอีเมลบัญชีผู้บันทึกกรณีล็อกอิน)
* `rollInfo`: ข้อมูลระบุตัวม้วน/คอยล์ (Lot, Roll Number, Coil, Width, Pattern)
* `reason` (ถ้ามี): สาเหตุในการแก้ไขรายการ
* `diffs`: รายการฟิลด์ที่มีการเปลี่ยนแปลง แต่ละรายการประกอบด้วย:
  * `field`: ชื่อตัวแปร (เช่น `usedMeters`, `ngMeters`, `soNumber`, `notes`)
  * `label`: ชื่อฟิลด์ภาษาไทย (เช่น `เมตรใช้งาน`, `เมตรเสีย (NG)`, `รหัส SO`)
  * `oldValue`: ค่าเดิมก่อนแก้ไข
  * `newValue`: ค่าใหม่หลังแก้ไข
  * `unit`?: หน่วย (เช่น `ม.`, `กก.`)
  * `delta`?: ผลต่างเชิงตัวเลข (เช่น `-5.0 ม.`)
* `summary`: ข้อความสรุปย่อภาษาไทยสำหรับแสดงผลทันที

### 1.2 การจัดเก็บและซิงค์ข้อมูล (Persistence & Sync)
* จัดเก็บใน LocalStorage (`pufoam_so_audit_logs_v1`) เป็นแคชออฟไลน์ที่รวดเร็ว
* เชื่อมโยงเข้ากับ Firestore Collection `so_audit_logs` เพื่อให้การตรวจสอบประวัติข้ามอุปกรณ์ไม่สูญหาย

## 2. โมดูลและคอมโพเนนต์ที่พัฒนา (Proposed Implementation)

### 2.1 โมดูลตรวจจับและคำนวณ Diff (`src/utils/auditLogger.ts`)
* ฟังก์ชัน `computeCutRecordDiff(oldRecord, newRecord)`:
  * ตรวจสอบเปรียบเทียบฟิลด์หลัก: `usedMeters`, `ngMeters`, `totalDeducted`, `soNumber`, `productionRound`, `notes`, `recordedBy`, `usageDate`
  * คำนวณผลต่าง (`delta`) เชิงบวก/ลบ
* ฟังก์ชัน `logSOAudit(entry)`: บันทึกรายการ UPDATE ลง LocalStorage และ Firestore
* ฟังก์ชัน `getSOAuditLogs(filters)`: ค้นหาและกรองประวัติการแก้ไขตาม SO, วันที่, ผู้บันทึก
* ฟังก์ชัน `exportAuditLogsToExcel(logs)`: ส่งออกรายการตรวจสอบประวัติเป็นไฟล์ Excel / CSV

### 2.2 เชื่อมต่อ Hook ในขั้นตอนแก้ไข (`src/App.tsx`)
* **เมื่อแก้ไขใบตัด SO (`handleUpdateCutRecord` / PU Sandwich)**:
  * บันทึกรายการ `UPDATE` โดยส่ง `oldRecord` และ `updatedRecord` ผ่าน `computeCutRecordDiff`
  * บันทึกชื่อผู้ดำเนินการ (`currentUserEmail` หรือช่างที่บันทึก)
* **เมื่อลบรายการตัด SO**:
  * **ยกเลิกไม่ต้องทำ** ตามคำขอของผู้ใช้ (ไม่มีการบันทึก Log การลบ)

### 2.3 แท็บมุมมอง Audit ในตารางประวัติ (`src/components/CuttingHistoryTable.tsx`)
* เพิ่มปุ่มสลับมุมมองด้านบน:
  * `[ รายการตัดทั้งหมด (Cuts) ]`
  * `[ ประวัติตรวจสอบการแก้ไข (Audit Trail & Diff) ]` พร้อมตัวนับจำนวนประวัติการแก้ไข
* ตัวกรองเฉพาะสำหรับ Audit:
  * กรองตามช่วงเวลา: วันนี้, 7 วันล่าสุด, เดือนนี้, ทั้งหมด
  * ช่องค้นหาตามรหัส SO หรือชื่อผู้แก้ไข
* ตารางแสดง Full Diff:
  * แสดงแท็กประเภทการแก้ไข (`แก้ไขข้อมูล`)
  * แสดงข้อมูลม้วนและรหัส SO
  * การ์ด Diff แสดงค่าเดิม (เส้นขีดฆ่าสีแดงอ่อน) $\rightarrow$ ค่าใหม่ (สีเขียว) พร้อมผลต่างตัวเลขชัดเจน
  * แสดงชื่อผู้ทำรายการและเวลาเป็นภาษาไทย

### 2.4 เชื่อมปุ่มดูประวัติเฉพาะ SO ในหน้ารายละเอียด (`src/components/SODetailModal.tsx`)
* เพิ่มแท็บ/ส่วน "ประวัติการแก้ไข SO นี้ (Revision History)":
  * กรอง Audit Logs เฉพาะ `soNumber` หรือ `recordId` นั้น
  * แสดง Timeline ลำดับเหตุการณ์ประวัติการแก้ไข

## 3. แผนการตรวจสอบและทดสอบ (Verification Plan)

### 3.1 การทดสอบการบันทึก Audit เมื่อมีการแก้ไข
1. ทดลองกดแก้ไขใบตัด SO (เช่น เปลี่ยนจาก 100 เมตร เป็น 95 เมตร และเพิ่ม NG 5 เมตร)
2. ตรวจสอบว่าระบบบันทึก Log ลงใน Audit Trail พร้อมแสดง Diff ของ `usedMeters` และ `ngMeters` ถูกต้อง
3. ตรวจสอบชื่อผู้แก้ไขและเวลาบันทึก

### 3.2 การยืนยันว่าไม่มีการบันทึก Audit เมื่อลบ
1. ทดลองลบใบตัด SO
2. ยืนยันว่าไม่มี Log การลบถูกสร้างขึ้นใน Audit Trail

### 3.3 การตรวจสอบการแสดงผลบน UI & Responsive
1. ตรวจสอบหน้าจอทั้งบน Desktop และ Tablet
2. ตรวจสอบว่าการสลับแท็บระหว่างรายการตัดปกติและ Audit Trail ทำงานรวดเร็ว ไม่มีอาการหน่วง
3. ทดสอบการค้นหา SO ในแท็บ Audit Trail

### 3.4 การ Build และ Lint
1. รัน `compile_applet` เพื่อยืนยันว่าไม่มี Type error
2. รัน `lint_applet` เพื่อยืนยันคุณภาพโค้ด
